# Server

The SpacetimeDB module. This package is not an HTTP server. `scripts/bootstrap.sh` publishes it with `spacetime publish --module-path server`.

Conventions: [../repo-conventions.md](../repo-conventions.md).

## Files

`src/index.ts` is the SpacetimeDB module: tables and reducers. `package.json` depends on `spacetimedb` `2.10.2` and exposes `typecheck` and `test`. `tsconfig.json` includes `src`.

`src/rules-by-type.ts` is the `rulesByType` registry. It starts empty. `registerGameRules` stores a shared `GameRules` value under that game's `GameDefinition.gameType`. Lookup is `rulesByType[gameType]`. An unregistered `gameType` is absent. `src/opening-state.ts` asks that registry for `initialState` when a table is created. `src/table-status.ts` maps a stored `phase` onto the table status and leaves a state with no phase unchanged. The dummy counter rules live in `src/shared/games/dummy-counter.ts`. Bluff rules live in `src/shared/games/bluff.ts`. President rules live in `src/shared/games/president.ts`. Go Fish rules live in `src/shared/games/go-fish.ts`. Crazy Eights rules live in `src/shared/games/crazy-eights.ts`. Rummy rules live in `src/shared/games/rummy.ts`. Blackjack rules live in `src/shared/games/blackjack.ts`. Spades rules live in `src/shared/games/spades.ts`. Hearts rules live in `src/shared/games/hearts.ts`. Poker rules live in `src/shared/games/poker.ts`. `src/bluff.test.ts` checks a six-seat deal, an empty table, a legal play, a rejected turn, a last-card win, and the event notes. `src/president.test.ts` checks a six-seat deal, a stable shuffle, a legal play, rejected turns and ranks, a cleared trick, scoring, and the end of the hand. `src/go-fish.test.ts` checks a deal, a shuffle, a legal ask, a rejected turn, scoring, and the end of the game. `src/crazy-eights.test.ts` checks a deal, a legal play, a rejected move, a wild eight, a draw, scoring, and both end conditions. `src/rummy.test.ts` checks a deal, a legal draw and meld, a rejected turn, an illegal run, a layoff, scoring, and both end conditions. `src/blackjack.test.ts` checks the shoe, bets, legal and illegal moves, scoring, and the end of a round. `src/spades.test.ts` checks a four-seat deal, bids, trump and follow-suit, nil and bag scoring, and a win at 500. `src/hearts.test.ts` checks a four-seat deal, the pass, legal and illegal plays, scoring, the moon, and the 100-point finish. `src/poker.test.ts` checks a deal, legal and illegal bets, side pots, and Hold'em, Omaha, and Oklahoma through showdown. `src/speaking-state.test.ts` checks lobby and table voice placement.

Tables, all `public: true`:

- `Lobby` — `id`, unique `code`, `status` (`open` | `closed`), `createdAt`, `discordChannelId` (empty unless `set_lobby_discord_channel` stored the Discord channel), `discordGuildId` and `discordLobbyVoiceChannelId` (empty unless `set_lobby_discord_voice` stored them)
- `LobbyMember` — unique per lobby and `clientId` via `byLobbyAndClient`. `discordUserId`, `discordUsername`, and `discordGlobalName` are empty for a web join. `discordDiscriminator` is stored only when Discord sends one. `name` stays the editable display name.
- `GameTable` — `byLobby`, plus `gameType`, seat limits, `stateJson`, `discordVoiceChannelId` (empty unless `set_table_discord_voice` stored it)
- `GameSeat` — `byTable`, optional `chips` and `seatState`
- `GameEvent` — `byTable`, `lobbyMemberId`, `type`, `payloadJson`, `createdAt`
- `SpeakingState` — `lobbyId`, `tableId` (empty for lobby voice), `lobbyMemberId`, `isSpeaking`, `lastUpdatedAt`. One row is one member in one voice channel.

Reducers: `create_lobby` (no arguments), `set_lobby_discord_channel` (`lobbyCode`, `discordChannelId`), `set_lobby_discord_voice` (`lobbyCode`, `discordGuildId`, `discordLobbyVoiceChannelId`), `clear_lobby_discord_voice` (`lobbyCode`), `close_lobby` (`lobbyCode`), `join_lobby` (`lobbyCode`, `clientId`, `name`), `join_lobby_with_discord` (`lobbyCode`, `clientId`, `name`, `discordUserId`, `discordUsername`, `discordGlobalName`, optional `discordDiscriminator`), `update_speaking_state` (`discordUserId`, `discordVoiceChannelId`, `isSpeaking`), `create_game_table` (`lobbyId`, `gameType`, optional `settings`), `set_table_discord_voice` (`tableId`, `discordVoiceChannelId`), `clear_table_discord_voice` (`tableId`), `remove_game_table` (`tableId`), `join_table` (`tableId`, `lobbyMemberId`), `leave_table` (`tableId`, `lobbyMemberId`), and `handle_game_intent` (`tableId`, `clientId`, `intentPayload`). `CaseConversionPolicy.None` keeps those names. The generated client calls `handle_game_intent` as `handleGameIntent` and `join_lobby_with_discord` as `joinLobbyWithDiscord`. Lobby codes are four characters from `CODE_ALPHABET` (no I, O, 0, 1).

## Changes

Edit `src/index.ts` for tables and reducers. Reject a bad call with `SenderError`. Keep table names PascalCase, columns camelCase, and reducer names snake_case.

Register a game in `src/rules-by-type.ts` with `GameRules` and `GameDefinition` from `src/shared/games`. Do not declare a second copy of those types.

Then publish and regenerate `client/src/module_bindings/`. `scripts/bootstrap.sh` is the path that already does this. Run `pnpm --filter server typecheck` after a type change.

`create_lobby` inserts a lobby with an empty `discordChannelId`, `discordGuildId`, and `discordLobbyVoiceChannelId`, and does not join the caller. `set_lobby_discord_channel` writes a Discord channel id onto an open lobby. A second channel id for that lobby is rejected. `set_lobby_discord_voice` writes `discordGuildId` and `discordLobbyVoiceChannelId` onto an open lobby that already has `discordChannelId`. `clear_lobby_discord_voice` clears that voice channel id. `close_lobby` sets `status` to `closed`. `set_table_discord_voice` writes `discordVoiceChannelId` onto a table in a lobby that already has `discordGuildId`. `clear_table_discord_voice` clears that id. `remove_game_table` deletes the table, its seats, and its events. The bot calls those voice reducers. Game rules stay in `handle_game_intent`. `join_lobby` reuses a `LobbyMember` for the same `(lobbyId, clientId)` and updates the name, leaving Discord fields as they are. A new web member stores those fields empty. `join_lobby_with_discord` uses that same `(lobbyId, clientId)` row and the browser `clientId`, and stores the Discord user id, username, and global name. A discriminator is stored only when the call includes one. Changing `name` later does not change `discordUserId`. A different Discord user id for a member that already has one is rejected. `src/discord-member.ts` checks that identity. The client maps the default display name from the Discord global name, otherwise the username, and joins without typing when the URL includes that profile. `update_speaking_state` resolves that Discord user id in the lobby or table voice channel and upserts `SpeakingState`. A Discord user who has not joined the lobby is ignored. `src/speaking-state.ts` maps the channel onto a lobby and an empty or table id. `create_game_table` inserts a `GameTable` in an open lobby with `status` `waiting_for_players`. Optional `settings` is a JSON object with `name`, `minPlayers`, `maxPlayers`, and, for Poker, `variation` (`holdem`, `omaha`, or `oklahoma`). When `rulesByType` has that `gameType`, `stateJson` is `initialState`. Otherwise it is `{}`. `join_table` seats that member until `maxPlayers` is reached, inserting a `GameSeat` at the lowest free `seatIndex`. After that insert, if the parsed `stateJson` is still `phase: "lobby"` and the seated count is at least `minPlayers`, `stateJson` is replaced with `rules.initialState` for the current seats and the table status follows that phase (`play` becomes `in_progress`). Dummy `{ count }` and stub `{ label }` have no lobby phase, so those tables stay as they were. `leave_table` deletes that member's `GameSeat` at the table. The member stays in the lobby, and the other seats stay. `handle_game_intent` loads that table, resolves `LobbyMember` and `GameSeat` from `clientId`, looks up `rulesByType[gameType]`, deserializes `stateJson`, calls `rules.applyIntent`, and writes the new state back onto the `GameTable` row. A stored `phase` of `finished` sets that row's status to `finished`. A state with no `phase` keeps the previous status. That row update is what subscribers receive. After a successful apply it inserts one `GameEvent` for that table: `lobbyMemberId`, `type` from the intent, `createdAt`, and `payloadJson` holding the apply order and the intent, plus a `note` when the game's optional `rules.eventNote` returns one (Bluff does for a play and a challenge, President does for a play, a pass, and the finish, Go Fish does for an ask, Crazy Eights does for a play, a draw, a pass, and the finish, Rummy does for a draw, meld, layoff, or discard, and Blackjack does for a bet, hit, stand, double, or split, and Spades does for a bid, a play, a trick, and a hand, and Hearts does for a pass and a play, and Poker does for a fold, check, call, bet, raise, discard, and the finish; dummy and stub have none). The event id ends in that order so a later replay can sort the table's rows. A rejected intent throws before the insert, so it adds no row. The module registers stub rules for gameType `stub`, counter rules for gameType `dummy` (`{ count }` plus an `increment` intent), Bluff rules for gameType `bluff`, President rules for gameType `president`, Go Fish rules for gameType `go_fish`, Crazy Eights rules for gameType `crazy_eights`, Rummy rules for gameType `rummy`, and Blackjack rules for gameType `blackjack`, and Spades rules for gameType `spades`, and Hearts rules for gameType `hearts`, and Poker rules for gameType `poker`.

## Leave alone

Do not add a host flag. Every member is equal.

Do not listen on a port from this package. SpacetimeDB is started by the CLI in `scripts/bootstrap.sh`.

Do not keep lobby or table state only on the client. New authoritative rows belong in this module.
