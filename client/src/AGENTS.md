# Client source

TypeScript for the Excalibur client. One folder holds the engine, the boot scene, sprite atlases, and the database connection. Tests sit next to the unit they check.

Style, resolution, and pixel filtering: [../../repo-conventions.md](../../repo-conventions.md). Generated bindings: [module_bindings/AGENTS.md](module_bindings/AGENTS.md).

## Files

- `main.ts` — reads or creates `clientId`, loads that client's color theme, then the engine at 960×540, fixed display, contain scale, loader, and `connectCardroom`. It paints this clientId's hands played and games won on the menu, the lobby, and the table. The connection host is not drawn. With no stored room, the app starts on `MenuScene`. Single Player calls `startSoloGame`, remembers that room, and opens the table. Leave from a solo room returns to the menu once this clientId's own membership is gone. A stored room opens the lobby scene with status `Rejoining room` and hides the create/join form. After the lobby subscription applies, it mounts the lobby panel, `LobbyScene`, and `GameScene` with that `clientId`, and hands the panel to the menu. If the page path is a four-character room code, `openJoin` runs with that code. A Discord user id on that URL is stored on the member when a username is present, and a known profile is the default name and joins without typing. A Discord user id alone asks the bot, and a failed lookup leaves the name empty. Entering a room from the menu opens the lobby scene (`boot`). Joining a table opens `GameScene`. Leave returns to the lobby and clears the stored table. A reload with no room code calls `join_lobby` again for the stored room. When that member's `GameSeat` or `Spectator` row and the `GameTable` are still there, it opens `GameScene`. A missing or closed room clears the stored room and returns to the menu. Any other rejoin error stays on the lobby scene.
- `client-id.ts` — `getOrCreateClientId` reads `clientId` from `localStorage` or stores a new UUID. The key name is `clientId`.
- `card-appearance.ts` — `getCardAppearance` reads `cardAppearance` from `localStorage` (same kind of per-browser preference as `clientId`), falling back to the `light` front and `classic` back. `setCardFrontStyle` and `setCardBackStyle` write it. `nextCardFrontStyle` and `nextCardBackStyle` cycle the menu's arrows. Never sent to SpacetimeDB.
- `client-stats.ts` — `statsCaption` is the `Hands N  Wins N` line. `statsForClient` reads the `ClientStats` row for this `clientId` and returns zeros for any other id. `clientStatsQuery` subscribes to that one row.
- `preferred-name.ts` — `preferredNames` in `localStorage` is a JSON object keyed by `clientId`. `rememberPreferredName` stores the name this client last set, and a blank name clears that id. `readPreferredName` returns it for that id only. `preferredNameForPrompt` keeps an explicit name (a Discord join) and otherwise uses the saved one.
- `last-room.ts` — `lastRoom` in `localStorage` holds the lobby code, the display name, and the table id while seated or watching. `rememberLobby` keeps the table id when the code matches. `forgetTable` clears only the table. `tableToReopen` returns that table id when the `GameTable` and this member's `GameSeat` or `Spectator` row are both still in the lobby.
- `boot-scene.ts` — boot scene. Draws the chosen table felt, two hearts, the card back, and one chip. `setStatus` shows a short rejoin or error line and starts empty, so the SpacetimeDB host is not drawn. `setTableStyle` repaints the felt. Also builds `cardAtlas` (the shared default look) and `personalCardAtlas()`, which reads `card-appearance.ts` and returns the matching `CardAtlas` for the front and back style a player picked, caching one per style pair.
- `menu-layout.ts` — menu geometry and pure logic: the button boxes, the Theme button, the Single Player picker, the Card Style layout, prompt boxes, how-to-play layout, markdown heading split and word wrap, and the looping pose of each background card or chip.
- `solo-room.ts` — `findSoloSeat` picks the newest solo lobby for this non-bot `clientId` and that lobby's newest table. `hasOwnMembership` is false once that person's row is gone.
- `menu-scene.ts` — `MenuScene`, the first scene. Title logo, drifting cards and chips, Create Room, Join Room, Single Player, How to Play (All Games), Card Style, and a Theme button that cycles this client's felt. Under the buttons, `Hands N  Wins N` is this clientId's stored stats. Single Player opens a picker for a catalog game, a seat count from that game's min to max, and a Poker variation. Confirming calls `connectSolo`. Create and Join open a canvas prompt (name, plus room code for Join) prefilled with the preferred name for this `clientId`. Each open field has an HTML input on the box for touch keyboards, and the canvas label shows the same value. `openJoin` fills that room code from a join URL. A non-empty default name submits Join without typing. A saved name only fills the field. Typing in the name field stores it for this `clientId`. Submit calls the lobby panel, shows its error in the prompt (a closed room reads `Room is closed. Get a new code.`), and on success opens the lobby scene. How to Play lists `GAME_CATALOG` and shows the selected game's `howToPlay` text. Card Style shows a front and a back row, each with arrows that cycle `card-appearance.ts` styles and save on every click, plus a live preview from `personalCardAtlas()`. Escape closes a prompt or the overlay. A click on Card Style, including Close, does not reach the menu buttons under the panel.
- `join-path.ts` — `roomCodeFromPath` reads a four-character lobby code from the URL path. The alphabet matches `CODE_ALPHABET` in the module. `discordIdentityFromSearch` reads `discordUserId` or `discord_user_id`, the username, the global name, and an optional `discordDiscriminator`. No user id means a web join.
- `join-errors.ts` — `joinFailureMessage` maps the module's `Table is full`, `Game already started`, `Game already ended`, and `Room closed` rejections onto four distinct red lines, and keeps any other module text. `wrapTableError` wraps a line to the 17 columns of the table-list error box. `join-errors.test.ts` checks each message and that it fits in two lines.
- `discord-join.ts` — `joinNameFromSearch` reads those same Discord query names. A known profile uses `defaultPlayerName`. An id alone uses `fetchDefaultPlayerName` on the bot. `cardroomBotUrl` reads `__CARDROOM_BOT_URL__`.
- `sheets.ts` — pixel sizes and grid math (`CARD_SIZE` 64, chip 32×44, table 129×80, logical 960×540). `fitViewport` is the contain size on every browser: the whole frame fits inside the visible area minus the safe-area insets, centered, never cropped. A narrower window leaves bars on the top and bottom. A shorter window leaves them on the left and right.
- `card-atlas.ts` — `{ rank, suit }` to a sprite. Hearts, diamonds, clubs, and spades share one grid. A suit with no sheet throws.
- `game-driver.ts` — `GameDriver<State>`, the render context, and pointer input. `RenderContext.cards` is the shared look for the table, piles, melds, and every other seat. `RenderContext.myCards` is the local player's own front and back style; only cards still in that player's own hand read it.
- `hand-hover.ts` — the hand hover curve. `handHoverLifts` raises at most three cards: the three centers closest to the pointer. The closest is highest, its neighbors sit lower and match when the pointer is on a center, and halfway between two centers those two are equal and above the outer neighbor. An end card has one neighbor. Cards outside that window stay at rest. `easeHoverLift` moves the drawn height toward that target. `placeCardLift` offsets the graphic and leaves the hit box on the card.
- `card-hit.ts` — which local-hand card is in front under a pointer. Later cards are in front. A raised card is in front of the cards it overlaps. A click toggles only that card, and a miss selects nothing.
- `bluff-layout.ts` — hand, pile, and opponent-back positions, plus which card can lift. Other Bluff seats use `bluffSeatFan`, a shallow arc around one pivot at the bottom of the fan. The seat name and the `xN` count sit outside that arc. `pileNotice` is the claim above the pile. `tablePrompt` says `Call a rank` only for the lead. `finishedLine` names the subscribed winner seat.
- `bluff-driver.ts` — Bluff `GameDriver`. Your hand is face up along the bottom, other hands are fanned card backs, and the discard pile is in the center. Play, Pass, and Challenge are full buttons only while that action is legal. The lead's rank buttons show only before a rank is called, and the chosen rank is filled. `Call a rank` and `Your turn` are only for the seat that must act. Play sends nothing until that rank is chosen. Any number of selected cards is one play. A legal card eases up on hover with its neighbors, from `hand-hover.ts`. A dealt or played card tweens. Phase `finished` draws `finishedLine` and sends no further move. A Play with no card selected, after a rank is already called, is still sent so the module rejects it. When the module rejects an intent, `intentRejected` blinks a red box over the Play, Pass, or Challenge button and the lifted cards.
- `president-layout.ts` — which card can lift, the lead or beat line, and the rank-order lines. Hand, pile, and opponent-back positions come from `bluff-layout.ts`.
- `president-driver.ts` — President `GameDriver`. Your hand is face up along the bottom, other hands are card backs, and the play pile is face up in the center. The rank order is drawn down the left. Play and Pass call `sendIntent`. A legal card eases up on hover with its neighbors, from `hand-hover.ts`. Phase `finished` draws `finishedLine` and sends no further move. A rejected intent blinks the Play or Pass button.
- `go-fish-layout.ts` — stock and book positions, which card can lift, and `finishedLine` for a Go Fish winner or a tie.
- `go-fish-driver.ts` — Go Fish `GameDriver`. Your hand is face up along the bottom, other hands are card backs, the stock is face down left of center, and each book is a small face-up card. Click a rank, then Ask on another seat. That calls `sendIntent`. A legal card eases up on hover with its neighbors, from `hand-hover.ts`. An Ask with no rank is still sent so the module rejects it. Phase `finished` draws `finishedLine` and sends no further move. A rejected ask blinks a red box over that Ask button and the lifted rank.
- `crazy-eights-layout.ts` — Crazy Eights positions on the shared hand, pile, and opponent-back layout, plus which card can lift, the stock stack, the suit buttons, and the wild-eight suit line.
- `crazy-eights-driver.ts` — Crazy Eights `GameDriver`. Your hand is face up along the bottom, other hands are card backs, the stock is a short stack of backs, and the discard pile is face up in the center. A wild eight draws the named suit. Play, Draw, and the suit buttons call `sendIntent`. Draw sends a pass when that is the only legal move. A legal card eases up on hover with its neighbors, from `hand-hover.ts`. A Play with no card selected is still sent so the module rejects it.
- `rummy-layout.ts` — stock, discard, and meld positions on the shared table. `finishedLine` names the subscribed winner seat.
- `rummy-driver.ts` — Rummy `GameDriver`. Your hand is face up along the bottom, other hands are card backs, melds sit by the seat that played them, and the stock and discard pile are in the center. Stock, Take, Meld, and Discard call `sendIntent`. A legal card eases up on hover with its neighbors, from `hand-hover.ts`. A dealt or played card tweens. Phase `finished` draws `finishedLine` and sends no further move. A Meld with no card selected is still sent so the module rejects it. When the module rejects an intent, `intentRejected` blinks a red box over that button and the lifted cards.
- `blackjack-layout.ts` — dealer hand, player hands, and bet-chip positions on the shared table. `finishedLine` names the subscribed winning seats, a push when a hand ties, or the dealer when every hand lost.
- `blackjack-driver.ts` — Blackjack `GameDriver`. The dealer hand is at the top (hole card face down until the round ends), your hand is face up along the bottom, other hands are face up, and each stake is a chip. Bet, Hit, Stand, Double, and Split call `sendIntent`. Phase `finished` draws `finishedLine` and sends no further move. A rejected intent blinks the button that sent it.
- `spades-layout.ts` — bid-button, trick, and partnership-board positions. `legalCard` is your turn during the trick. `finishedLine` names the winning side and the scores.
- `spades-driver.ts` — Spades `GameDriver`. It reuses the Bluff hand and opponent-back layout. Your hand is face up, other hands are backs, and the current trick sits toward the center. Partnership bids, tricks, and a chip for each side are drawn beside the felt. Bid numbers and Play call `sendIntent`. A legal card eases up on hover with its neighbors, from `hand-hover.ts`. Phase `finished` draws `finishedLine` and sends no further move. A rejected bid or play blinks the control that sent it.
- `hearts-layout.ts` — trick and penalty positions on the shared hand and seat layout. A played card sits past its seat's card backs. An opponent's taken cards sit in a lane away from the center, and your own sit above your hand. `pointCards` keeps hearts and the queen of spades, with the queen last so it draws on top. `legalCard` asks the Hearts rules. `finishedLine` names the subscribed winner seat.
- `hearts-driver.ts` — Hearts `GameDriver`. Your hand is face up along the bottom, other hands are card backs, the current trick sits toward the center, and taken hearts and the queen of spades sit in a row per seat. Each seat shows its points as `N pts`, and `Hearts broken` shows once hearts may lead. Pass and Play call `sendIntent`. A legal card eases up on hover with its neighbors, from `hand-hover.ts`. A dealt or played card tweens. Phase `finished` draws `finishedLine` and sends no further move. An empty Play is still sent so the module rejects it. `intentRejected` blinks the Pass or Play button and the lifted cards.
- `poker-layout.ts` — board, pot, and action-button positions on the shared hand and seat layout. `finishedLine` names the subscribed winning seats. `seatLabelOrigin`, `seatNote`, `droppedPositions`, and `bannerX` place the chip count, the fold, bet, all-in, or showdown-hand note, the dropped cards, and the winner banner.
- `poker-driver.ts` — Poker `GameDriver`. Your hole cards are face up along the bottom, other hole cards are backs until showdown, the board and the pot sit in the center, and Fold, Check, Call, Bet, and Raise call `sendIntent`. An Oklahoma discard clicks a hole card: your cards ease up with their neighbor from `hand-hover.ts` and get a red "Drop" outline on hover, and a card you dropped stays small and dimmed beside your hand under "Dropped". Folded seats dim their cards. Phase `finished` draws `finishedLine` and sends no further move. A rejected intent blinks the button that sent it.
- `event-messages.ts` — `readStoredEvent` reads `{ order, note }` from a `GameEvent.payloadJson`, and `eventMessage` turns a Bluff, President, Go Fish, Crazy Eights, Rummy, Blackjack, Spades, Hearts, or Poker note into one short line (a called bluff, a play, a pass, a finish, an ask, a draw, a meld, a layoff, a discard, a bet, a hit, a stand, a double, a split, a bid, a trick, a score, the queen, a moon, or a winner). Dummy and stub events have no note and stay silent.
- `chip-atlas.ts` — color or table value to a face sprite and a stack sprite on `chips-no-outline.png`.
- `table-atlas.ts` — `green`, `purple`, or `red` to a table sprite. Green is the default.
- `theme.ts` — `theme` in `localStorage` is `{ clientId, style }`. `getTheme` reads the felt for this `clientId`. `saveTheme` stores it. A different `clientId` keeps the default green felt.
- `connect.ts` — `DbConnection.builder()`, the connection phase, and the `Lobby`, `LobbyMember`, `GameTable`, `VoicePresence`, and `SpeakingState` subscription, plus this `clientId`'s `ClientStats` row. `subscribeLobbyTables` adds `GameTable`, `GameSeat`, and `Spectator` for one lobby. Host and database come from `__SPACETIMEDB_HOST__` and `__SPACETIMEDB_DB__`. `sdkHost` rewrites `ws://` and `wss://` to `http://` and `https://` before `withUri`, because the SDK opens the websocket itself. A disconnected or failed socket makes Create and Join show `Could not reach the server. Try again.` instead of waiting.
- `game-scene.ts` — seat names for one table. `seatAnchorsFor` puts three players on the bottom, left, and right, gives the fourth the top, and spreads larger tables around the felt. The known table in the joined lobby, that table's `GameTable` / `GameSeat` / `Spectator` / `TableChatMessage` subscription queries, `spectatingLine` for a watcher with no seat, and `dummyStateFromJson` for the dummy counter. Also the `TABLE_CHAT_BUTTON`, `TABLE_CHAT_PANEL`, `TABLE_CHAT_TEXT`, `TABLE_CHAT_INPUT`, and `TABLE_CHAT_SEND_BUTTON` geometry for `TableChatOverlay`.
- `voice-presence.ts` — `lobbyVoiceMemberIds` and `tableVoiceMemberIds` read `VoicePresence` rows, and `headsetActor` draws the small headset from `HEADSET_PIXELS`. The lobby Players list and the seat name plates draw it for a member the bot saw in the matching voice channel. Web-only members have no row.
- `button-style.ts` — shared button face: Press Start 2P at 8px, height 28, and `buttonCaptionPos`, which centers the label in the face. The tall main-menu stack, icon chips, Ask, and Watch keep their own size. Antialiasing stays off.
- `canvas-ui.ts` — shared canvas palette, `canvasText` (Press Start 2P, family `"Press Start 2P"`), and `panelRect`.
- `html-field.ts` — one real HTML input per canvas text box (name, room code, lobby chat, table chat). While that box can be typed in, the input sits on it (kept in place every frame and on resize) so the finger lands on the input itself and a phone or tablet keyboard opens in that gesture. Nothing focuses it later from a canvas pointerup, and focus never passes `preventScroll`. On a coarse pointer, `focus()` only places the input. The input text is transparent, its native caret is hidden, and the font stays 16px so iOS does not zoom. The canvas draws a gold block caret (`CARET_GOLD`, at least two pixels wide and about one em tall) at the insertion index using the pixel font's advance, for the name, the room code, and chat. Once focused, `keyboardLift` reads `visualViewport` and lifts the canvas host so the box stays above the keyboard. `input` events sanitize the string and the canvas label draws the same value. Physical keys use that input too, and the key does not bubble into the Excalibur handler. Antialiasing stays off.
- `how-to-play.ts` — `definitionFor(gameType)` over `bluffGameDefinition`, `presidentGameDefinition`, `goFishGameDefinition`, `crazyEightsGameDefinition`, `rummyGameDefinition`, `blackjackGameDefinition`, `spadesGameDefinition`, `heartsGameDefinition`, `pokerGameDefinition`, and `dummyGameDefinition`, plus `layoutHowToPlay`, which turns a definition's `howToPlay` markdown into a title and wrapped lines.
- `how-to-play-overlay.ts` — `HowToPlayOverlay`. The `?` control at top right opens a dimmed window with that table's instructions. `?`, Close, or Escape closes it. The mouse wheel scrolls long text. While open, Leave Table and intents are blocked. Opening the table chat overlay closes it.
- `table-chat.ts` — pure per-table chat logic: `applyChatKey` (printable ASCII, wider than `applyFieldKey`), `tableChatMessagesForTable` (one table's `TableChatMessage` rows, oldest first), and `tableChatLine` (`"You: ..."` for the sender, the member's name otherwise).
- `mobile-shell.ts` — phone and tablet shell, `mountMobileShell`. A device is `(pointer: coarse) and (hover: none)`. In portrait it covers the game with a green and gold panel (`Rotate the phone to landscape`) and a fullscreen button. In landscape it shows a small fullscreen button until the browser is fullscreen. Where `requestFullscreen()` works the button enters fullscreen, then calls `screen.orientation.lock('landscape')`. On iPhone it cannot, so an upright phone keeps the panel and a note names Share, then Add to Home Screen. `display-mode: standalone` hides the button. `isMobileDevice`, `isPortrait`, `visibleSize` (from `visualViewport`), and `readSafeInsets` are shared with `main.ts` and `html-field.ts`.
- `touch-targets.ts` — `installTouchTargets`. On a coarse pointer it grows the collider of each small pointer-handling actor to at least `TOUCH_TARGET` (44px) without changing its art, and splits the extra between close neighbours so hit boxes do not overlap. `touchBoxes` is the pure geometry.
- `table-chat-overlay.ts` — `TableChatOverlay`. The `Chat` control at top center opens a dimmed window with that table's chat history and a text field. An HTML input sits on that field while the window is open so a touch keyboard can type, and the canvas label shows the same draft. Enter or Send calls `sendTableChat`; Close or Escape closes it. `setTable` resets the draft and closes the window when the table id changes. While open, Leave Table and intents are blocked, and opening How to Play closes it.
- `game-scene-view.ts` — `GameScene`. Green table, seat labels, Leave Table, the `?` overlay, and the dummy counter. `Hands N  Wins N` sits between the chat button and the status HUD. A member with a `Spectator` row and no `GameSeat` sees `Spectating` and sends no intent. Bluff tables use `BluffDriver`, President tables use `PresidentDriver`, Go Fish tables use `GoFishDriver`, Crazy Eights tables use `CrazyEightsDriver`, Rummy tables use `RummyDriver`, Blackjack tables use `BlackjackDriver`, Spades tables use `SpadesDriver`, Hearts tables use `HeartsDriver`, and Poker tables use `PokerDriver` on the subscribed `stateJson`. A seated member speaking in that table's voice channel gets a green glow around the name plate and a speech bubble beside it. Each shows the status HUD left of the `?` control. Dummy tables hide the HUD. `sendIntent` calls `handleGameIntent`. The count text is the subscribed dummy `stateJson`. It also subscribes to this table's `GameEvent` rows and shows each new event line, and each rejection reason in red, in a strip under the title that fades after about three seconds. Events that were already stored when the table opened are not replayed. It also subscribes to this table's `TableChatMessage` rows for the `Chat` overlay.
- `status-hud.ts` — `STATUS_HUD` box, `bluffStatusHud`, `presidentStatusHud`, `goFishStatusHud`, `crazyEightsStatusHud`, `rummyStatusHud`, `blackjackStatusHud`, `spadesStatusHud`, `heartsStatusHud`, and `pokerStatusHud`. The three HUD lines come from the subscribed `stateJson`: `turnSeatIndex` as a seated name, `phase`, and a round. For Bluff the round is the called rank name, or Call while the lead has not chosen. For President it is the trick to beat, or the President title when the hand is over. Go Fish puts the book count in that third line. Crazy Eights uses the suit in play or the winner's score. Rummy's round line is the stock count, or the winner's deadwood when the hand is over. For Blackjack it is Bets, Hand, or Done. For Spades the round is the hand number, and the phase is Bid or Play. Hearts names the turn or the pass, and the hand or pass direction. Poker names the street or the discard, and the variation. Bluff stores no hand or round counter.
- `lobby.ts` — name and room-code field editing, which `LobbyMember.name` rows belong to the joined lobby, the table-list rows for that lobby (`tableLines`, which marks tables the member sits at and counts only `GameSeat` rows toward `currentSeats/maxPlayers`), `tableGroups` and `listLayout` (one header per game type, catalog games first, rows past the panel counted as hidden), `WATCH_BUTTON` for a non-seated viewer, and `GAME_CATALOG`, plus `lobbyLaunchedFromDiscord` and `discordBadgeBox` for the Launched from Discord badge. That catalog offers Bluff from `bluffGameDefinition`, President from `presidentGameDefinition`, Go Fish from `goFishGameDefinition`, Crazy Eights from `crazyEightsGameDefinition`, Rummy from `rummyGameDefinition`, Blackjack from `blackjackGameDefinition`, Spades from `spadesGameDefinition`, Hearts from `heartsGameDefinition`, and Poker from `pokerGameDefinition` (`gameType`, display name, min and max players, how-to-play). Creating a Poker table also chooses Hold'em, Omaha, or Oklahoma. Stub and dummy stay on the rules registry and are not Create Table choices.
- `speaking.ts` — pure speaking-indicator logic. `lobbySpeakers` and `tableSpeakers` turn `SpeakingState` rows into the member ids that are speaking (lobby voice rows have an empty `tableId`; a missing row or `isSpeaking` false is absent). `SpeakingFader` eases each member's level over `SPEAKING_FADE_MS` (200ms). `BUBBLE_RECTS` is the 14×11 speech bubble with three dots, and `glowRects` is the stepped seat glow. `speaking.test.ts` also scans the client sources and fails on Discord hosts, microphone and audio APIs, or `fetch` outside `discord-join.ts` (the local default-name lookup).
- `speaking-view.ts` — draws those pixel rects as Excalibur canvases. `speechBubble` and `seatGlow` return actors that fade with the fader and are invisible while the member is not speaking.
- `lobby-panel.ts` — canvas name field, optional room code, and the joined room. Each of those boxes, and the rename box, has an HTML input while it is on screen so a touch keyboard can type. The canvas label shows the same value. The Players list draws a headset after a name in the lobby voice channel, then a `speechBubble` when that member is speaking. It tells `LobbyScene` which lobby was joined. `mountLobbyPanel` returns `enter(kind, name, code)` so the menu can create or join and read the error. A Discord identity calls `joinLobbyWithDiscord` and keeps the browser `clientId`. A web join calls `joinLobby`. After join, Save writes a new display name through that same reducer. A successful create, join, or Save stores the room with `rememberLobby` and stores that display name with `rememberPreferredName`. The name field starts with the saved name for this `clientId`. Its keyboard handler only runs while the lobby scene is active.
- `lobby-ambience.ts` — idle card positions behind the lobby and `idleCardPose`, a slow whole-pixel bob and small sway.
- `lobby-scene.ts` — `LobbyScene` on the boot scene. A top-center banner shows the room code. Leave Room asks for confirmation. Leave and Cancel are scene actors above the dialog, and the dialog panel answers those same boxes. Confirm calls `leave_lobby`, which drops that member’s seats and returns the client to the menu. Cancel stays. Deleting this member or the joined lobby, including the one-hour idle teardown, returns to the menu too. A stored room skips the menu on load and rejoins. Under the chat panel, `Hands N  Wins N` is this clientId's stored stats. The Chat heading sits above the first message. The chat composer has an HTML input on its box while the lobby is on screen. The name field and the chat composer do not share the keyboard. The list groups tables by game type, with table name, `currentSeats/maxPlayers`, and status per row. A `YOU` badge marks the table this member sits at. A small `Launched from Discord` badge sits under the banner while the joined lobby's `Lobby.discordChannelId` is not empty, and is absent for a web lobby. Faint idle cards bob behind the felt. Create Table picks a game and max players. A table click calls `joinTable` and opens `GameScene`. Watch, and a click on a full table, call `spectateTable` instead. That opens `GameScene` without a player seat. When the module refuses (full table, game already started or ended, room closed), the lobby stays and the table-list error box shows that refusal's own line from `join-errors.ts`. `openLobby` resolves once that lobby's `GameTable`, `GameSeat`, and `Spectator` rows are subscribed. `reopenIfSeated` opens `GameScene` when the stored table and this member's seat or spectator row are both still present.
- `vite-env.d.ts` — `__SPACETIMEDB_HOST__`, `__SPACETIMEDB_DB__`, and `__CARDROOM_BOT_URL__`.
- `test-setup.ts` — Node stubs so Excalibur can load under Vitest.
- `*.test.ts` — Vitest. Pixel checks read `../public/assets/` with `pngjs`. `table-atlas.test.ts`, `html-field.test.ts`, and `mobile-shell.test.ts` use `@vitest-environment happy-dom`.

`sheets.ts` is shared geometry. The atlases map names onto that geometry. `boot-scene.ts` still places a few cells itself for the static demo.

## Changes

Keep `ImageFiltering.Pixel` on every `ImageSource`. Change a cell in `sheets.ts` or the atlas map, then update the test that reads the PNG.

The suit sheets are not a straight Ace-to-King grid. Row 0 column 0 is blank. Row 2 is 10, Jack index, Jack face, Queen index, Queen face. Row 3 starts with the King index and the King face. Jokers are a separate two-cell sheet. Diamonds, clubs, and spades use that same grid. Read the comment in `card-atlas.ts` before moving a rank.

`CardAtlas` takes the hearts image, the card back, and optional sheets for the other suits. `ChipAtlas` takes the chip sheet. `TableAtlas` constructs its own image sources from `/assets/table-*.png`.

New connection behavior goes through `connect.ts`. Import tables and reducers from `module_bindings`, which re-exports the generated module.

Each card-game driver's `syncCards` (or equivalent) tags every card it places with `personal: true` only when that card is still in the local player's own hand (or, for Blackjack and Poker, the local player's own seat). `placeCard` reads `ctx.myCards` for those and `ctx.cards` for everything else: piles, melds, tricks, the dealer hand, the board, and every other seat. A card a player already played is table state and stays on `ctx.cards`, even if that seat is `self`.

Run `pnpm test` and `pnpm --filter client typecheck` from the repo root.

## Leave alone

Do not edit `module_bindings/` by hand.

Do not turn antialiasing on. `fitViewport` in `sheets.ts` is the contain scale `main.ts` applies on every browser, and the canvas stays `image-rendering: pixelated`.

Do not validate a move here. `sendIntent` forwards the click. The module decides.
