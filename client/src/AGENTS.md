# Client source

TypeScript for the Excalibur client. One folder holds the engine, the boot scene, sprite atlases, and the database connection. Tests sit next to the unit they check.

Approved table design: [../../docs/design-system.md](../../docs/design-system.md).

Style, resolution, and pixel filtering: [../../repo-conventions.md](../../repo-conventions.md). Generated bindings: [module_bindings/AGENTS.md](module_bindings/AGENTS.md).

## Files

- `main.ts` — reads or creates `clientId`, loads that client's table color and background, then the engine at 960×540, fixed display, contain scale, loader, and `connectCardroom`. It draws the authenticated player's lifetime multiplayer winnings on the menu, lobby, and table. The connection host is not drawn. With no stored room, the app starts on `MenuScene` and does not show a loading scene. Single Player calls `startSoloGame`, remembers that room, and opens the table. Leave from a solo room returns to the menu once this clientId's own membership is gone. A stored table shows `Loading table` on an empty table felt while the session resolves. A stored room with no table shows `Loading room`. The create/join form stays hidden. After the lobby subscription applies, it mounts the lobby panel, `LobbyScene`, and `GameScene` with that `clientId`, and hands the panel to the menu. If the page path is a four-character room code, `openJoin` runs with that code. A Discord user id on that URL is stored on the member when a username is present, and a known profile is the default name and joins without typing. A Discord user id alone asks the bot, and a failed lookup leaves the name empty. Entering a room from the menu opens the lobby scene (`boot`). Joining a table opens `GameScene`. Leave returns to the lobby and clears the stored table. A reload with no room code calls `join_lobby` again for the stored room. When that member's `GameSeat` or `Spectator` row and the `GameTable` are still there, it opens `GameScene` directly and does not show the lobby on the way. When the player is in the room and not at a table, it opens the lobby. A missing or closed room clears the stored room and returns to the menu. Any other rejoin error stays on that loading line.
- `client-id.ts` — `getOrCreateClientId` reads `clientId` from `localStorage` or stores a new UUID. The key name is `clientId`.
- `card-appearance.ts` — `getCardAppearance` reads `cardAppearance` from `localStorage` (same kind of per-browser preference as `clientId`), falling back to the `light` front and `classic` back. `setCardFrontStyle` and `setCardBackStyle` write it. `stepCardFrontStyle` and `stepCardBackStyle` move the Theme panel's arrows. `nextCardFrontStyle` and `nextCardBackStyle` still cycle one step forward. Never sent to SpacetimeDB.
- `lifetime-winnings.ts` — formats the caller's lifetime winnings in chips, including half-chips.
- `preferred-name.ts` — `preferredNames` in `localStorage` is a JSON object keyed by `clientId`. `rememberPreferredName` stores the name this client last set, and a blank name clears that id. `readPreferredName` returns it for that id only. `preferredNameForPrompt` keeps an explicit name (a Discord join) and otherwise uses the saved one.
- `last-room.ts` — `lastRoom` in `localStorage` holds the lobby code, the display name, and the table id while seated or watching. `rememberLobby` keeps the table id when the code matches. `forgetTable` clears only the table. `tableToReopen` returns that table id when the `GameTable` and this member's `GameSeat` or `Spectator` row are both still in the lobby.
- `reload-landing.ts` — `reloadLoadingLine` is `Loading table` when the saved session has a table id, `Loading room` when it is only a room, and absent when nothing is saved. `reloadLanding` is `table` when the player is still seated or watching, `lobby` when they are in the room and not at a table, and `menu` when they are in neither. `reload-landing.test.ts` checks those three landings.
- `boot-scene.ts` — boot scene. Draws the chosen table felt and a status line. No sample cards and no chip stack. A second instance is the reload loading scene, so lobby actors stay on `boot` until that landing is the lobby. `setStatus` shows `Loading table`, `Loading room`, or a rejoin error, and starts empty, so the SpacetimeDB host is not drawn. `setTableStyle` repaints the felt. `setBackground` paints the margin around it. Also builds `cardAtlas` (the shared default look) and `personalCardAtlas()`, which reads `card-appearance.ts` and returns the matching `CardAtlas` for the front and back style a player picked, caching one per style pair.
- `menu-layout.ts` — menu geometry and pure logic: the button boxes, the Theme panel (card front, card back, table color, and background, each with a preview), the Single Player picker, prompt boxes, how-to-play layout, markdown heading split and word wrap, and the looping pose of each background card or chip.
- `solo-room.ts` — `findSoloSeat` picks the newest solo lobby for this non-bot `clientId` and that lobby's newest table. `hasOwnMembership` is false once that person's row is gone.
- `menu-scene.ts` — `MenuScene`, the first scene. Title logo, drifting cards and chips, Create Room, Join Room, Single Player, How to Play (All Games), and Theme. Under the buttons, Lifetime winnings shows the player's settled multiplayer gains. Single Player opens a picker for a catalog game, a seat count from that game's min to max, and a Poker variation. Confirming calls `connectSolo`. Create and Join open a canvas prompt (name, plus room code for Join) prefilled with the preferred name for this `clientId`. Each open field has an HTML input on the box for touch keyboards, and the canvas label shows the same value. `openJoin` fills that room code from a join URL. A non-empty default name submits Join without typing. A saved name only fills the field. Typing in the name field stores it for this `clientId`. Submit calls the lobby panel, shows its error in the prompt (a closed room reads `Room is closed. Get a new code.`), and on success opens the lobby scene. How to Play lists `GAME_CATALOG` and shows the selected game's `howToPlay` text. Theme shows card front, card back, table color, and background. Each row has arrows and a preview (a card face, a card back, the table sprite, and a background swatch). A click saves that choice on this browser and repaints the menu. Escape closes a prompt or the overlay. A click on Theme, including Close, does not reach the menu buttons under the panel.
- `join-path.ts` — `roomCodeFromPath` reads a four-character lobby code from the URL path. The alphabet matches `CODE_ALPHABET` in the module. `discordIdentityFromSearch` reads `discordUserId` or `discord_user_id`, the username, the global name, and an optional `discordDiscriminator`. No user id means a web join.
- `join-errors.ts` — `joinFailureMessage` maps the module's `Table is full`, `Game already started`, `Game already ended`, and `Room closed` rejections onto four distinct red lines, and keeps any other module text. `wrapTableError` wraps a line to the 17 columns of the table-list error box. `join-errors.test.ts` checks each message and that it fits in two lines.
- `discord-join.ts` — `joinNameFromSearch` reads those same Discord query names. A known profile uses `defaultPlayerName`. An id alone uses `fetchDefaultPlayerName` on the bot. `cardroomBotUrl` reads `__CARDROOM_BOT_URL__`.
- `sheets.ts` — pixel sizes and grid math (`CARD_SIZE` 64, chip 32×44, table 129×80, logical 960×540). `fitViewport` is the contain size on every browser: the whole frame fits inside the visible area minus the safe-area insets, centered, never cropped. A narrower window leaves bars on the top and bottom. A shorter window leaves them on the left and right.
- `card-atlas.ts` — `{ rank, suit }` to a sprite. Hearts, diamonds, clubs, and spades share one grid. A suit with no sheet throws.
- `game-driver.ts` — `GameDriver<State>`, the render context, and pointer input. `RenderContext.cards` and `RenderContext.myCards` are this browser's saved card front and back. Own-hand cards still pass `personal: true`.
- `hand-hover.ts` — the hand hover curve and shared pointer-focus layer. `isFocused` follows the nearest card independently of animation height or selection; `placeCardLift` places that card above every selected/easing neighbour. Selected cards retain resting scale and a modest lift; equal lifts retain left-to-right order. All nine drivers forward focus. `hand-layering.test.ts` covers every driver plus selection and rapid focus changes. The collider remains stable. `handHoverLifts` raises at most three cards: the three centers closest to the pointer. The closest is highest, its neighbors sit lower and match when the pointer is on a center, and halfway between two centers those two are equal and above the outer neighbor. An end card has one neighbor. Cards outside that window stay at rest. `easeHoverLift` moves the drawn height toward that target. `placeCardLift` offsets the graphic and leaves the hit box on the card.
- `card-hit.ts` — which local-hand card is in front under a pointer. Later cards are in front. A raised card is in front of the cards it overlaps. A click toggles only that card, and a miss selects nothing.
- `table-presentation.ts` — the shared rail fan and the lower-right action cluster. `seatFan` lays each opponent hand on that seat's table edge, rotated so the card bottoms sit on the edge and the name plus the extra line (count, chips, or bet) sit in the open middle. Every opponent fan card draws at the same 64px size as the local hand and the community cards. The spread tightens when more seats share the edge or the hand is longer, and a fan may sit farther out so the name stays in the open middle. Top fans open downward, and a corner seat may lean. `actionBox` wraps Fold, Check, Call, Bet, Raise, and the other games' Play, Pass, Draw, Meld, and Discard buttons two across, below the felt. Fold uses the Leave Table red. Rank, suit, and bid pickers use the same green band, left of the cluster. `askChipBox` puts a Go Fish Ask chip in the fan gap.
- `bluff-layout.ts` — hand, pile, and which card can lift. Opponent fans come from `table-presentation.ts`. `pileNotice` is the claim above the pile. `tablePrompt` says `Call a rank` only for the lead. Rank buttons sit in the green band. `finishedLine` names the subscribed winner seat.
- `classic-card-layout.ts` — shared width-aware hand capacity, centered resting hand, compact control boxes and bounded opponent backs for the classic game family.
- `president-classic-layout.ts` / `president-table-ui.ts` — stable rank ordering, public combination geometry, six-seat counts/status, strength guide and full finish-order presentation.
- `classic-table-ui.ts` — reusable classic canvas header, measured typography, rectangular controls and unbordered personal band.
- `prize-pool-badge.ts` / `prize-pool.ts` — scene-owned gold trophy prize badge for all seven entry-fee games, exact retained funding total, and settled-pool preservation. Classic headers omit player-count metadata and the legacy phase HUD. Casino pots/stacks remain separate.
- `bluff-classic-layout.ts` / `bluff-table-ui.ts` — approved Bluff checkpoint: six seats, bounded opponent backs, exact counts, responsive paged hands, public rank/claim/pile, and dynamic personal status including out-of-turn Challenge.
- `bluff-driver.ts` — classic Bluff driver: readable, width-aware paging on both input types (nine opening cards fit without paging), selection across pages, shared hold/hover inspection, a public pile and compact private opponent backs. `BluffTableUi` owns the header, exact counts, rank/claim/pile labels, personal state and full winner/prize result. Play/Pass stay turn-specific; Challenge remains available outside the turn when eligible. The thirteen-rank picker lives in the empty public center for the lead. Challenge pickup still holds, moves, lifts and settles without revealing another hand. No game logic is changed.

- `president-layout.ts` — which card can lift, the lead or beat line, and the rank-order lines. Hand and pile positions come from `bluff-layout.ts`. Opponent fans come from `table-presentation.ts`.
- `president-driver.ts` — classic President `GameDriver`. Uses shared responsive hand/back geometry and readable `PresidentTableUi`: current combination and strength guide in the public center, exact opponent counts, compact Play/Pass and final six-player finish order. Large hands retain selections across pages and resize; hold/hover inspects. Remaining cards stay private at finish. Server rejections blink the actual visible control and selected cards.
- `go-fish-layout.ts` — stock and book positions, which card can lift, and `finishedLine` for a Go Fish winner or a tie.
- `go-fish-driver.ts` — classic Go Fish driver. Stable rank-grouped private hands share responsive paging and hold/hover inspection. Tap a held rank, choose a non-empty opponent in the central target picker, then confirm Ask in the compact action column. Books opens a bounded collection view. Public last-ask results never expose another player’s stock draw; remaining hands stay private at finish.
- `crazy-eights-layout.ts` — Crazy Eights positions on the shared hand and pile, plus which card can lift, the stock stack, the suit buttons in the green band, and the wild-eight suit line. Opponent fans come from `table-presentation.ts`.
- `crazy-eights-driver.ts` — seven-player classic rail, paged private hand, stock/discard and named suit. `crazy-eights-classic-layout.ts` / `crazy-eights-table-ui.ts` own bounded geometry and the four-suit wild-eight picker; Play/Draw/Pass controls reflect the subscribed step. Remaining hands stay private at finish.
- `rummy-layout.ts` — stock, discard, and meld positions on the shared table. `finishedLine` names the subscribed winner seat.
- `rummy-driver.ts` — six-player classic rail and deadwood-first personal band. `rummy-classic-layout.ts` / `rummy-table-ui.ts` own stock/discard, compact phase actions, and an owner-labelled public meld viewer with separate meld/card paging and explicit layoff. Private selection persists across pages; remaining hands stay hidden at finish.
- `blackjack-layout.ts` — dealer hand at the top of the felt, your hand on the bottom row, other hands on the rail fan, and bet chips in that fan gap. `finishedLine` names the subscribed winning seats, a push when a hand ties, or the dealer when every hand lost.
- `blackjack-driver.ts` — five-player classic house table plus a distinct dealer. `blackjack-classic-layout.ts` / `blackjack-table-ui.ts` bound public split-hand browsing and the local hand, keep each bet/total/result attached to its hand, preserve the dealer hole card, and reserve readable 260px house actions. Server countdown/top-up come through `RenderContext.houseGame`.
- `spades-layout.ts` — bid buttons wrapped in the green band, the trick, and partnership-board positions. Play sits in the shared cluster. `legalCard` is your turn during the trick. `finishedLine` names the winning side and the scores.
- `spades-driver.ts` — four-player classic partnership table. `spades-classic-layout.ts` / `spades-table-ui.ts` keep partner opposite the local player, show team identity and bids/tricks, offer a central bid picker, owner-labelled public trick and bounded team Scores view. Private hands page and remain hidden at finish.
- `hearts-layout.ts` — trick and penalty positions on the shared hand and seat layout. A played card sits inward of that seat's rail fan. An opponent's taken cards sit clear of that fan, and your own sit above your hand. `pointCards` keeps hearts and the queen of spades, with the queen last so it draws on top. `legalCard` asks the Hearts rules. `finishedLine` names the subscribed winner seat.
- `hearts-driver.ts` — four-player classic score-first table. `hearts-classic-layout.ts` / `hearts-table-ui.ts` align physical seats with left/right/across passing, preserve three-card selection across pages, and show owner-labelled trick cards, hearts-broken state and public penalty/total Scores. Remaining private hands never turn over at finish.
- `poker-layout.ts` — community board and personal-card positions, bottom-band action and stake boxes, card flip, and countdown helpers. `pokerPersonalMode` chooses waiting, acting, discard, stake, result, or spectator content and governs when controls are visible. `pokerActionBox` keeps every action in the bottom band below y=436 and inside the viewport. `frontStakeControl` resolves a pointer to one visible stake face.
- `poker-driver.ts` — owns only the local hole-card actors, the public board, inspection animation, and legal betting controls. `PokerTableUi` owns opponent presentation. Fold, Check, and Call send immediately; Bet and Raise open the legal canvas slider above larger betting-chip stacks, with the additional contribution (excluding earlier street bets) at their left. Min/max endpoints and denomination previews use that same amount; server intents retain street-total semantics. Poker reveal rules remain in the shared rules. An Oklahoma discard uses the shared lift without a colored card border. Finished hands keep the server's next-hand countdown or paused/closed state.
- `poker-table-ui.ts` — classic Poker rail seating, compact card fans and unboxed names, prominent stacks/pot, and a dynamic personal bottom bar. Pot chips share the betting preview’s face sprites, scale and layer spacing; repeated denominations split into horizontal piles of at most four, bounded at nine piles. Its right side replaces waiting/latest-action text with local-turn controls, discard instructions, or results/countdown/top-up; there is no global banner on the felt. Oklahoma contenders reveal their two retained cards at their own seat; folds and uncalled hands stay hidden. The header calls existing Leave/Chat/Help flows and hides legacy triggers and their child graphics. `poker-table-ui.test.ts` checks full clusters for 2–8 players, eight-player spectators, and personal state transitions.
- `classic-table-design.ts` — shared classic tokens, typography, measured captions, restrained borders, seat slots and header boxes. `isClassicGame` recognizes all nine catalog games; stub/dummy retain the fallback. Follow `docs/design-system.md` for game-specific composition and evidence.
- `ui-text.ts` — locally hosted Chakra Petch SemiBold for table information and controls, blended text at quality 2, measured caption centering. Pixel menu/input typography and native-field caret metrics remain separate.
- `poker-chip-motion.ts` — bounded cosmetic chip transfers derived from accepted state changes, with duplicate/new-deal suppression, reduced-motion support, and cleanup. `poker-chip-motion.test.ts` checks accepted bets, final-call settlement, replay suppression, and slider limits. Poker's amount control is a thick touch/keyboard canvas slider above a larger chip preview and a left-aligned numeric total; the countdown shows only winning showdown cards in a central large-card view, with Next for split pots.
- `event-messages.ts` — `readStoredEvent` reads `{ order, note }` from a `GameEvent.payloadJson`, and `eventMessage` turns a Bluff, President, Go Fish, Crazy Eights, Rummy, Blackjack, Spades, Hearts, or Poker note into one short line (a called bluff, a play, a pass, a finish, an ask, a draw, a meld, a layoff, a discard, a bet, a hit, a stand, a double, a split, a bid, a trick, a score, the queen, a moon, or a winner). Dummy and stub events have no note and stay silent.
- `chip-atlas.ts` — color or table value to a face sprite and a stack sprite on `chips-no-outline.png`.
- `table-atlas.ts` — `green`, `purple`, or `red` to a table sprite. Green is the default.
- `theme.ts` — `theme` in `localStorage` is `{ clientId, style, background }`. `getTheme` reads the felt for this `clientId` (`green`, `purple`, or `red`). `getBackground` reads the page and felt-margin color (`green`, `purple`, `red`, or `black`). Green (`#145c38`) is the default for both. Black is `#000000` and is not a table felt. `saveTheme` and `saveBackground` keep the other field. A different `clientId` keeps the defaults.
- `client-look.ts` — `readClientLook` and `tableScenePaint` combine the saved table color, background, card front, and card back. `GameScene` paints from `tableScenePaint` when it opens and on each refresh.
- `page-background.ts` — `applyPageBackground` sets `--cardhouse-bg` on the page so the bars around the 960×540 frame match the saved background.
- `connect.ts` — `DbConnection.builder()`, the connection phase, and the `Lobby`, `LobbyMember`, `GameTable`, `VoicePresence`, and `SpeakingState` subscription, plus the authenticated caller's `my_lifetime_winnings` view. `subscribeLobbyTables` adds `GameTable`, `GameSeat`, and `Spectator` for one lobby. Host and database come from `__SPACETIMEDB_HOST__` and `__SPACETIMEDB_DB__`. `sdkHost` rewrites `ws://` and `wss://` to `http://` and `https://` before `withUri`, because the SDK opens the websocket itself. A socket that closes, rejects its identity token, sits idle through a long hidden gap, or never answers a reducer is replaced. The new socket gets the same subscriptions and row listeners, and the menu, lobby, and table show `Reconnecting...` until it is up. The scenes stay where they were. `clientId` and `theme` are not touched. A kept identity token is `stdbToken` in localStorage. The first connect, before any socket has succeeded, still makes Create and Join show `Could not reach the server. Try again.` instead of waiting. `connection-session.ts` is the pure reconnect decision. `live-connection.ts` is the stable object the scenes hold.
- `connection-session.ts` — when to open the socket again. A drop after the first successful connect waits on a backoff. A hidden gap of at least 60 seconds, a closed socket, or a resume while a retry is already waiting opens immediately. `Failed to verify token` drops `stdbToken` and connects anonymously. `clientId` and `theme` are not keys this module writes.
- `live-connection.ts` — the object `GameScene`, `LobbyScene`, and the lobby panel keep. `attach` points it at a new socket, registers the same row listeners, and sends the open subscriptions again. A reducer call on a dead socket rejects with `Reconnecting...` instead of queuing forever.
- `game-scene.ts` — seat names for one table. `seatAnchorsFor` keeps this player at the bottom. Two players sit across the top. Three use the left and right and leave the top empty. Four adds the top. Five and six fill the top. Seven and eight put two seats on each side and two or three across the top. The order stays fixed when a player reconnects. The known table in the joined lobby, that table's `GameTable` / `GameSeat` / `Spectator` / `TableChatMessage` subscription queries, `spectatingLine` for a watcher with no seat, and `dummyStateFromJson` for the dummy counter. Also the `TABLE_CHAT_BUTTON`, `TABLE_CHAT_PANEL`, `TABLE_CHAT_TEXT`, `TABLE_CHAT_INPUT`, and `TABLE_CHAT_SEND_BUTTON` geometry for `TableChatOverlay`.
- `voice-presence.ts` — `lobbyVoiceMemberIds` and `tableVoiceMemberIds` read `VoicePresence` rows, and `headsetActor` draws the small headset from `HEADSET_PIXELS`. The lobby Players list and the seat name plates draw it for a member the bot saw in the matching voice channel. Web-only members have no row.
- `button-style.ts` — shared button face: Press Start 2P at 8px, height 28, and `buttonCaptionPos`, which centers the label in the face. The tall main-menu stack, icon chips, Ask, and Watch keep their own size. Antialiasing stays off.
- `canvas-ui.ts` — shared canvas palette, `canvasText` (Press Start 2P, family `"Press Start 2P"`), and `panelRect`.
- `html-field.ts` — one real HTML input per canvas text box (name, room code, lobby chat, table chat). While that box can be typed in, the input sits on it (kept in place every frame and on resize) so the finger lands on the input itself and a phone or tablet keyboard opens in that gesture. Nothing focuses it later from a canvas pointerup, and focus never passes `preventScroll`. On a coarse pointer, `focus()` only places the input. The input text is transparent, its native caret is hidden, and the font stays 16px so iOS does not zoom. The canvas draws a gold block caret (`CARET_GOLD`, at least two pixels wide and about one em tall) at the insertion index using the pixel font's advance, for the name, the room code, and chat. Once focused, `keyboardLift` reads `visualViewport` and lifts the canvas host so the box stays above the keyboard. `input` events sanitize the string and the canvas label draws the same value. Physical keys use that input too, and the key does not bubble into the Excalibur handler. Antialiasing stays off.
- `how-to-play.ts` — `definitionFor(gameType)` over `bluffGameDefinition`, `presidentGameDefinition`, `goFishGameDefinition`, `crazyEightsGameDefinition`, `rummyGameDefinition`, `blackjackGameDefinition`, `spadesGameDefinition`, `heartsGameDefinition`, `pokerGameDefinition`, and `dummyGameDefinition`, plus `layoutHowToPlay`, which turns a definition's `howToPlay` markdown into a title and wrapped lines.
- `how-to-play-overlay.ts` — `HowToPlayOverlay`. The `?` control at top right opens a dimmed window with that table's instructions. `?`, Close, or Escape closes it. The mouse wheel scrolls long text. While open, Leave Table and intents are blocked. Opening the table chat overlay closes it.
- `table-chat.ts` — pure per-table chat logic: `applyChatKey` (printable ASCII, wider than `applyFieldKey`), `tableChatMessagesForTable` (one table's `TableChatMessage` rows, oldest first), `tableChatLine` (`"You: ..."` for the sender, the member's name otherwise), and `tableChatButtonVisible` (false when that table's lobby is solo).
- `mobile-shell.ts` — phone and tablet shell, `mountMobileShell`. A device is `(pointer: coarse) and (hover: none)`. In portrait it covers the game with a green and gold panel (`Rotate the phone to landscape`) and a fullscreen button. In landscape it shows a small fullscreen button until the browser is fullscreen. Where `requestFullscreen()` works the button enters fullscreen, then calls `screen.orientation.lock('landscape')`. On iPhone it cannot, so an upright phone keeps the panel and a note names Share, then Add to Home Screen. `display-mode: standalone` hides the button. `isMobileDevice`, `isPortrait`, `visibleSize` (from `visualViewport`), and `readSafeInsets` are shared with `main.ts` and `html-field.ts`.
- `touch-targets.ts` — `installTouchTargets`. On a coarse pointer it grows the collider of each small pointer-handling actor to at least `TOUCH_TARGET` (44px) without changing its art, and splits the extra between close neighbours so hit boxes do not overlap. `touchBoxes` is the pure geometry.
- `table-chat-overlay.ts` — `TableChatOverlay`. On a multiplayer table the `Chat` control at top center opens a dimmed window with that table's chat history and a text field. A solo table hides that control. An HTML input sits on that field while the window is open so a touch keyboard can type, and the canvas label shows the same draft. Enter or Send calls `sendTableChat`; Close or Escape closes it. `setTable` resets the draft and closes the window when the table id changes. While open, Leave Table and intents are blocked, and opening How to Play closes it.
- `game-scene-view.ts` — `GameScene`. The saved table felt and background, seat labels in the fan gap, Leave Table, the `?` overlay, and the dummy counter. Lifetime winnings shows the same multiplayer total as the lobby and the menu. A solo table hides the `Chat` button. A member with a `Spectator` row and no `GameSeat` sees `Spectating` and sends no intent. Bluff tables use `BluffDriver`, President tables use `PresidentDriver`, Go Fish tables use `GoFishDriver`, Crazy Eights tables use `CrazyEightsDriver`, Rummy tables use `RummyDriver`, Blackjack tables use `BlackjackDriver`, Spades tables use `SpadesDriver`, Hearts tables use `HeartsDriver`, and Poker tables use `PokerDriver` on the subscribed `stateJson`. A seated member speaking in that table's voice channel gets a green glow around the name plate and a speech bubble beside it. Catalog card games use their classic header and game-owned status area; the legacy HUD stays hidden. Dummy tables keep the fallback. `sendIntent` calls `handleGameIntent`. The count text is the subscribed dummy `stateJson`. It also subscribes to this table's `GameEvent` rows and shows each new event line, and each rejection reason in red, in a strip under the title that fades after about three seconds. Events that were already stored when the table opened are not replayed. It also subscribes to this table's `TableChatMessage` rows for the `Chat` overlay.
- `status-hud.ts` — `STATUS_HUD` box, `bluffStatusHud`, `presidentStatusHud`, `goFishStatusHud`, `crazyEightsStatusHud`, `rummyStatusHud`, `blackjackStatusHud`, `spadesStatusHud`, `heartsStatusHud`, and `pokerStatusHud`. The three HUD lines come from the subscribed `stateJson`: `turnSeatIndex` as a seated name, `phase`, and a round. For Bluff the round is the called rank name, or Call while the lead has not chosen. For President it is the trick to beat, or the President title when the hand is over. Go Fish puts the book count in that third line. Crazy Eights uses the suit in play or the winner's score. Rummy's round line is the stock count, or the winner's deadwood when the hand is over. For Blackjack it is Bets, Hand, or Done. For Spades the round is the hand number, and the phase is Bid or Play. Hearts names the turn or the pass, and the hand or pass direction. Poker names the street, the discard, or Showdown, and the variation, and does not print a seat number. Bluff stores no hand or round counter.
- `lobby.ts` — name and room-code field editing, which `LobbyMember.name` rows belong to the joined lobby, the table-list rows for that lobby (`tableLines`, which marks tables the member sits at and counts only `GameSeat` rows toward `currentSeats/maxPlayers`), `tableGroups` and `listLayout` (one header per game type, catalog games first, rows past the panel counted as hidden), `WATCH_BUTTON` for a non-seated viewer, and `GAME_CATALOG`, plus `lobbyLaunchedFromDiscord` and `discordBadgeBox` for the Launched from Discord badge. That catalog offers Bluff from `bluffGameDefinition`, President from `presidentGameDefinition`, Go Fish from `goFishGameDefinition`, Crazy Eights from `crazyEightsGameDefinition`, Rummy from `rummyGameDefinition`, Blackjack from `blackjackGameDefinition`, Spades from `spadesGameDefinition`, Hearts from `heartsGameDefinition`, and Poker from `pokerGameDefinition` (`gameType`, display name, min and max players, how-to-play). ## Changes

Keep `ImageFiltering.Pixel` on every `ImageSource`. Change a cell in `sheets.ts` or the atlas map, then update the test that reads the PNG.

The suit sheets are not a straight Ace-to-King grid. Row 0 column 0 is blank. Row 2 is 10, Jack index, Jack face, Queen index, Queen face. Row 3 starts with the King index and the King face. Jokers are a separate two-cell sheet. Diamonds, clubs, and spades use that same grid. Read the comment in `card-atlas.ts` before moving a rank.

`CardAtlas` takes the hearts image, the card back, and optional sheets for the other suits. `ChipAtlas` takes the chip sheet. `TableAtlas` constructs its own image sources from `/assets/table-*.png`.

New connection behavior goes through `connect.ts`. Import tables and reducers from `module_bindings`, which re-exports the generated module.

Each card-game driver's `syncCards` (or equivalent) tags every card it places with `personal: true` only when that card is still in the local player's own hand (or, for Blackjack and Poker, the local player's own seat). `placeCard` reads `ctx.myCards` for those and `ctx.cards` for everything else: piles, melds, tricks, the dealer hand, the board, and every other seat. `GameScene` passes the saved Theme atlas for both, so this browser's card front and back are what the table draws. A card a player already played is table state and stays on `ctx.cards`, even if that seat is `self`.

Run `pnpm test` and `pnpm --filter client typecheck` from the repo root.
