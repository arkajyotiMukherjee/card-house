# Docs

The plan for the card room. These files describe scenes, drivers, and games the code does not implement yet.

Conventions: [../repo-conventions.md](../repo-conventions.md).

## Files

- `architecture.md` — lobby, tables, seats, client vs SpacetimeDB, future `GameRules` and `GameDriver` shapes.
- `implementation.md` — milestone order from the skeleton through more games and Discord.
- `discord-bot-architecture.md` — Discord bot, voice channels, identity, and speaking indicators.
- `ui-ux.md` — in-canvas layout, 960×540, contain scaling, pixel buttons.

Prettier ignores `docs/`. Match the plain markdown already in these files.

## Changes

Update a doc when you change the plan it describes. Keep names aligned with the module when you write about something that already exists: tables are `Lobby`, `LobbyMember`, `GameTable`, `GameSeat`, `Spectator`, `GameEvent`, `LobbyChatMessage`, `TableChatMessage`, `ClientStats`, `VoicePresence`, `SpeakingState`, `TableCleanupSchedule`, `RoomCaps`, and `LobbyIdleConfig` (`LobbyIdleSweep` is the private schedule); reducers in the module are `create_lobby`, `set_lobby_discord_channel`, `set_lobby_discord_voice`, `clear_lobby_discord_voice`, `close_lobby`, `set_lobby_idle_timeout`, `close_idle_lobbies`, `join_lobby`, `join_lobby_with_discord`, `update_speaking_state`, `update_voice_presence`, `create_game_table`, `set_table_discord_voice`, `clear_table_discord_voice`, `remove_game_table`, `clean_empty_tables`, `set_empty_table_idle_timeout`, `join_table`, `spectate_table`, `leave_table`, `handle_game_intent`, `send_lobby_chat_message`, `send_table_chat`, and `set_room_caps`. `send_lobby_chat_message` inserts a `LobbyChatMessage` row (`lobbyId`, the sender's `LobbyMember.id`, `body`, `createdAt`) for a member of an open lobby; every member subscribed to that lobby sees it, and a member of a different lobby does not. `send_table_chat` inserts a `TableChatMessage` for a sender who holds a `GameSeat` or a `Spectator` row at that table; a lobby member who is neither is rejected, so a message stays scoped to the one table and does not reach the rest of the lobby. `Lobby.discordChannelId` is empty for a web lobby. A web `LobbyMember` has an empty `discordUserId`. `discordGuildId`, `discordLobbyVoiceChannelId`, and `GameTable.discordVoiceChannelId` stay empty until the bot stores a voice channel. `discord-bot/` calls `create_lobby`, then `set_lobby_discord_channel`, for `/cardhouse create`, then `set_lobby_discord_voice` when Discord accepts the lobby voice channel. `/cardhouse status` reads `Lobby`, `LobbyMember`, and `GameTable` and does not call a reducer. `/cardhouse close` calls `close_lobby` only when that lobby has no members and no seats at its tables. The voice watch then deletes that room's open voice channels. A join URL with a Discord user id stores that id and uses the mapped default name.

The running code is the check for current behavior. `architecture.md` still lists Discord and the card-game rules that are not in `server/src/index.ts`. The module registers the `dummy` counter, Bluff (`bluff`), President (`president`), Go Fish (`go_fish`), Crazy Eights (`crazy_eights`), Rummy (`rummy`), Blackjack (`blackjack`), Spades (`spades`), Hearts (`hearts`), and Poker (`poker`). `handle_game_intent` appends a `GameEvent` after each applied intent. `GameScene` draws Bluff with `BluffDriver`, President with `PresidentDriver`, Go Fish with `GoFishDriver`, Crazy Eights with `CrazyEightsDriver`, Rummy with `RummyDriver`, Blackjack with `BlackjackDriver`, Spades with `SpadesDriver`, Hearts with `HeartsDriver`, and Poker with `PokerDriver`: the local hand is face up, other hands are a rotated fan on that seat's table edge (backs, except Blackjack and a Poker showdown for seats still in the hand, which stay face up), center play stays on the felt, and the action buttons sit in one cluster below the felt at the lower right. President also draws the rank order. Go Fish draws a face-down stock and books beside each seat. Crazy Eights draws the discard face up and a wild eight's named suit. Rummy draws melds by the seat that played them, plus the stock and discard pile. Blackjack draws the dealer hand, player hands, and bets. Spades uses `SpadesDriver` on the same hand layout, with partnership bids and the trick in the center. Hearts uses `HeartsDriver` on the same table: the trick sits toward the center, and taken hearts and the queen of spades stay beside the seat that won them. A Bluff, President, Go Fish, Crazy Eights, Rummy, Blackjack, Spades, or Hearts table stays in `phase: "lobby"` until `join_table` has seated `minPlayers`. When that state is `phase: "finished"`, both clients draw the subscribed winner. Create Table offers Bluff, President, Go Fish, Crazy Eights, Rummy, Blackjack, Spades, Hearts, and Poker from the shared definitions. A Poker table chooses Hold'em, Omaha, or Oklahoma when it is created. Poker draws hole cards, five face-down community cards that flip when that street is dealt, the pot, and Fold, Check, Call, Bet, and Raise in that cluster. Bet and Raise open an amount control in that cluster; Confirm sends the chosen amount and Cancel returns to the buttons. Fold, Check, and Call stay one tap. SB and BB sit in the fan gap beside the names of the seats that posted the blinds. A finished hand stays up for 10 seconds, with the winner banner, any showdown hole cards, and a countdown from `Next hand in 10` to `Next hand in 1`, then deals the next hand while two or more players remain. The community cards sit below the pot. Top-edge fans use the same card size as side-edge fans. Solo bots check or call from their own cards and the price of the call, bet or raise a strong hand, and fold only a weak hand that has to pay. `GameScene` has a `?` control that opens a How to Play overlay with the table's `GameDefinition.howToPlay`, and a `Chat` control on a multiplayer table that opens a per-table chat overlay over `TableChatMessage` rows for the open table only. A solo table hides that Chat control. The table's `Hands N  Wins N` line counts this sitting only. The menu and the lobby keep the lifetime totals from `ClientStats`. Opening one of those overlays closes the other. A reload with no room code shows `Loading table` or `Loading room` on the empty table, calls `join_lobby` again for the stored room, and opens that table directly when the member's `GameSeat` or `Spectator` row is still there, without showing the lobby on the way. A room with no table opens the lobby. No stored room opens the menu. `spectate_table` lets a member watch without a `GameSeat`, so the seat count stays at `maxPlayers` and that member is not dealt a hand. Leave Table clears the stored table, so the next reload opens the lobby. Create Room and Join Room start with the preferred name stored for this `clientId` under `preferredNames` in localStorage. A different browser profile does not see that name.
